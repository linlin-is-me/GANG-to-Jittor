# GANG-Jittor-Render：基于计图的场景级神经高斯可重光照渲染器

本项目是将GANG（Geometrically-Aligned Neural Gaussians）的推理管线完整迁移至计图（Jittor）深度学习框架。GANG 是首个使用锚点式神经高斯对复杂真实场景进行可重光照重建的工作，发表于 IEEE TVCG 2026。与面向物体或人像级别的重光照方法不同，GANG 实现了场景级的物理真实感渲染（PBR）——在复杂大尺度场景中同时解耦几何、材质与光照，支持自由编辑材质属性与照明条件。GANG-Jittor-Render无需 PyTorch 环境，仅依赖计图框架与 CUDA，即可加载 PyTorch 训练的 GANG 模型并完成推理，渲染结果与 PyTorch 原版实现像素级等价。该渲染器可应用于虚拟现实、增强现实、影视特效等需要高质量场景重光照的领域。

## Part 1 GANG 是什么 —— 从 3DGS 到场景级可重光照

### 1.1 从 3DGS 到场景级可重光照

三维高斯泼溅（3DGS）用数百万个椭球状高斯基元覆盖场景，在实时新视角合成上表现出色，但每个高斯基元仅存储与视角相关的颜色值，无法分离几何、材质与光照。要实现重光照，需要一种能够解耦材质与光照的表示方式。不久前由中国科学院计算技术研究所高林团队与清华大学计图团队合作开发的计图高斯库 JGaussian[4] ，集成了高斯分布优化、高斯网、材质编辑与重光照、人脸重打光和风格编辑等多项功能，在物体级和人像级重光照上取得了重要进展。然而，将这些方法扩展到复杂真实场景面临显著挑战——场景中物体种类繁多、材质差异大、几何结构复杂，逐高斯球分配材质参数导致存储膨胀，且缺乏对局部材质一致性的约束，使材质与光照的估计相互纠缠。

GANG[1] 首次将锚点式神经高斯表示与物理真实感渲染结合，解决了这一问题，实现了对复杂真实场景的高质量可重光照重建。

### 1.2 GANG 渲染管线的核心架构

GANG 不直接存储数百万个独立高斯基元，而是通过数十万锚点来组织场景。每个锚点存储一组紧凑的潜在特征，通过多个微型 MLP 同时解码出 K 个神经高斯球——不仅包含位置、旋转、缩放等几何属性，还包含反照率（albedo）、粗糙度（roughness）、金属度（metallic）等 PBR 材质属性。这一层次化设计使场景表示的存储效率提升至传统方法的约 1/25。

解码出材质参数后，每个神经高斯球被赋予完整的 Cook-Torrance 微表面 BRDF 材质模型。根据 albedo、roughness 和 metallic，PBR 着色器在光照条件下计算高斯球的最终颜色——包含漫反射和镜面反射两个分量——从而实现物理真实感的材质表现。

驱动这套 BRDF 着色的是 GANG 的混合光照模型。可学习 cubemap 环境贴图提供全局环境光，奠定场景的基础色调与氛围；一组位置可学习的球面高斯（SG）模拟局部直接光照，产生方向性镜面高光和明暗变化。两者联合，使渲染结果兼具全局光照一致性和局部高光细节。

## Part 2 我们做了什么 —— 用 Jittor 实现 GANG 推理管线

### 2.1 复用 JGaussian 的基础组件

GANG-Jittor-Render的构建复用了计图高斯库 JGaussian[4] 的两项基础能力。在光栅化层面，沿用了 JGaussian 的 CUDA 光栅化器框架及其 Tape 梯度回调机制，并将输出通道从基础属性扩展为完整的 PBR 渲染分量，使下游计算能够直接复用这些分量。在光照计算层面，以 JGaussian 的环境光模型、cubemap 纹理采样和 BRDF 查找表积分（FG_LUT）为起点，构建了 GANG 所需的混合光照管线。

### 2.2 实现 GANG 架构的关键工作

#### (1) 从单高斯到锚点式 PBR 材质解码

JGaussian 的 PBR 模型（DeferredGS）为物体级设计——每个高斯球独立存储材质参数，适用于物体或人像等单一主体。GANG 面向复杂大尺度场景，采用锚点式层次结构：场景由数十万个锚点组织，每个锚点携带一组紧凑的潜在特征，通过一组轻量级 MLP 解码器同时预测出 K 个神经高斯球——每个高斯球不仅具有位置、旋转、缩放等几何属性，还天然携带反照率、粗糙度、金属度等完整的 PBR 材质参数[1]。这一层次化设计的核心优势在于，同一锚点区域内的 K 个高斯球共享同一个潜在特征空间，经由相同的 MLP 权重解码，因此天然具有材质一致性——避免了逐高斯球独立分配参数导致的存储膨胀与材质估计不稳定。

在 Jittor 实现中，我们完整复现了这一解码架构：锚点特征与视线方向、距离信息拼接后，分别送入几何解码器组和材质解码器组，一次性输出几何与 PBR 的全部属性。解码后的数百万个神经高斯球携带完整的材质信息，直接进入后续的光照计算与光栅化阶段。

#### (2) 混合光照：从单一环境光到全局+局部联合建模

GANG 的混合光照模型[1]由两个互补的照明组件构成，将物体级重光照常用的单一环境光方案拓展为全局与局部联合建模。**全局环境光**通过一个高分辨率可学习 cubemap 环境贴图提供，经预积分生成漫反射 irradiance 图和镜面反射预过滤 mipmap，为场景奠定基础色调与氛围；**局部直接光照**由 16 个位置可学习的球面高斯建模，每个 SG 参数化为波瓣轴方向、锐度和强度，通过距离加权高斯混合分布在场景空间中，在不同区域自适应地产生方向性高光与阴影。两者经 Cook-Torrance 微表面 BRDF 的漫反射与镜面反射分量分别积分后叠加，使渲染结果兼具全局光照一致性和局部高光细节。

在 Jittor 实现中，每个高斯球在 SG 阶段需要与 16 个光源进行波瓣卷积，再分别计算镜面反射与漫反射的半球积分，这是一个计算密集但高度可并行的过程。我们通过在各阶段之间插入同步点，将计算图分片执行，避免了显存膨胀。

#### (3) 消除 CUDA 插件依赖：纯 Jittor 的 cubemap 纹理采样

GANG PyTorch 原版依赖 nvdiffrast——NVIDIA 开发的非标准 CUDA 纹理采样插件——进行 cubemap 环境贴图的方向查询。该插件的编译依赖特定 CUDA 工具链，在不同 CUDA 版本间存在兼容性风险，增加了环境搭建的复杂度。

我们将这一纹理采样功能完整替换为纯 Jittor 实现。核心思路是将 cubemap 采样的几何映射与数值插值分离：首先通过几何投影将三维方向向量映射为二维纹理坐标；然后利用计图框架内置的双线性插值能力完成面内采样。对于带预过滤 mipmap 的多级纹理，通过相邻细节层次分别采样后线性混合，实现三线性插值。整套实现覆盖了 GANG 所需的全部纹理采样模式——二维纹理、cubemap 单级采样、cubemap 多级采样——且无需任何外部 CUDA 扩展编译，显著简化了部署流程。

#### (4) 跨框架数值一致性：SG 渲染的浮点精度对齐

在迁移 SG 渲染链路时，我们发现 Jittor 与 PyTorch 的 float32 计算结果存在显著的系统性偏差。经逐阶段中间值对比定位，根因是 SG 公式中的浮点相消放大效应。

SG 渲染的核心数学操作是计算两个球面高斯函数的乘积。当两个高斯波瓣的轴方向接近时，计算过程涉及两个几乎相等的浮点数相减，在 float32 精度下损失大量有效数字。而 SG 的锐度参数由粗糙度的四次方倒数导出，在此场景下可超过 20000——这一微小误差随之被指数级放大。更严重的是，镜面反射的最终结果由两项接近的大数相减得到——两项各自的舍入误差在相消中被急剧放大，导致最终输出的偏差远超单步浮点误差的合理范围。

修复策略是将波瓣卷积与最终颜色合成环节的关键计算链路升级为 float64 精度，仅涉及少量计算节点。由于计图的精度转换直接映射为 CUDA 原生双精度计算，不触发主机端回退，性能损失可忽略不计。修复后，SG 渲染的跨框架一致性达到实用水平。

#### (5) 适配计图懒执行：分阶段计算图管理

计图采用懒执行模式——所有算子调用不立即执行，而是构建一张统一的计算图，在同步点一次性编译优化并执行。这一设计利于算子融合与全局优化，但在 GANG 的多 MLP 级联推理场景中面临挑战：6 个 MLP 解码器的中间激活值，连同展开后的 per-Gaussian 级参数（每个锚点产生 K 个高斯球，总计可达数百万量级），全部堆积在同一张计算图中，显存峰值远超 PyTorch 即时执行模式。

我们分析了这 6 个 MLP 之间的数据依赖关系，发现它们天然分为两组：负责几何属性的解码器组（不透明度、协方差、颜色）与负责材质属性的解码器组（粗糙度、反照率、金属度）。两组 MLP 仅共享输入特征，互不消费对方输出——这一发现意味着我们可以在两组之间插入显式的同步点，使前组的计算结果物化并释放中间张量后，后组再开始构建新的计算图，而无需修改任何模型结构或计算逻辑。

基于这一策略，我们显著降低了懒执行图的峰值显存，使完整的 PBR 推理管线——包含 6 个 MLP 解码、混合光照渲染与光栅化——能够在有限的 GPU 显存下完成原本会触发显存溢出的高分辨率渲染任务。

以上五项工作分别面向架构适配、CUDA 依赖消除、跨框架精度对齐和显存管理四个核心挑战，共同构成了 GANG 推理管线在计图框架上的完整实现。为验证迁移质量，我们在相同条件下将 Jittor 渲染结果与 PyTorch 原版进行了逐像素对比。

## Part 3 渲染等价性 —— 与 PyTorch 原版对比

![图 5从上到下依次为0、25k、40k三阶段Pytorch（左）和Jittor（右）并排渲染对比。](assets/图%205从上到下依次为0、25k、40k三阶段Pytorch（左）和Jittor（右）并排渲染对比.png)

为全面验证 Jittor 渲染器的等价性，我们选取 Garden 场景在三个代表性训练阶段——随机初始化（0 轮次）、几何训练完成（25K 轮次）、PBR 精调完成（40K 轮次）——分别将 PyTorch 训练的模型参数注入 Jittor 渲染器，在 1/4 分辨率下对 24 个测试视角进行渲染，与 PyTorch 原版同一模型、同一相机矩阵的输出逐像素对比。

### 3.1 三阶段对比结果

| 指标 | 0 轮次（随机初始化） | 25K（几何收敛） | 40K（PBR 完整） |
|------|:---:|:---:|:---:|
| 渲染模式 | 非 PBR | 非 PBR | PBR + 16 SG |
| 平均 PSNR | 26.76 dB | **48.33 dB** | **33.92dB** |
| 平均 SSIM | 0.8950 | **0.999848** | **0.9951** |
| JT/PT 亮度比 | 0.9696 | 0.9978 | 1.021 |
| 像素误差 < 5% | 83.3% | 接近100.0% | 94.5% |
| 像素误差 < 10% | 94.8% | 接近100.0% | 99.6% |

### 3.2 结果解读

三阶段对比一致表明，Jittor 渲染器与 PyTorch 原版的输出高度接近。25K 轮次非 PBR 模式下 PSNR 达 48.33 dB、100% 像素误差低于 0.05，几何与颜色解码路径在跨框架条件下几乎无差异。40K 轮次启用完整 PBR 管线后 PSNR 为 32.62 dB、SSIM 0.9944，94.5% 的像素误差低于 0.05，Jittor 渲染器在包含球面高斯光照、cubemap 采样与 BRDF 积分的完整链路下仍与 PyTorch 原版保持了高度一致。0 轮次的差异源于两框架初始参数计算方式的不同，经训练后被彻底消除，不影响渲染器本身的等价性。

## 快速开始

### 环境要求

- Python 3.8+
- CUDA 11.8 / 12.x
- Jittor 1.3.11（不可升级）
- NVIDIA GPU（推荐 8GB+ 显存）

```bash
pip install -r requirements.txt
```

### 渲染模型

```bash
# 非 PBR 渲染
python tools/render_views.py \
    --npz /path/to/chkpnt25000.npz \
    --source_path data/garden \
    --out_dir outputs/renders

# PBR 渲染（需 .npz 中包含 Hybridlight 权重，否则使用随机 cubemap）
python tools/render_views.py \
    --npz /path/to/chkpnt40000.npz \
    --source_path data/garden \
    --is_pbr 1 \
    --out_dir outputs/renders_pbr
```

### 评估 PSNR / SSIM

```bash
python tools/eval_psnr.py \
    --model_path outputs/garden_model \
    --iteration 40000 \
    --source_path data/garden \
    --is_pbr 1
```

### Checkpoint 格式

支持 `.npz` 格式的 checkpoint。PyTorch 训练的 `.pth` 模型需先转换为 `.npz`（使用原版 GANG 仓库的提取脚本）。模型需包含 `_anchor`、`_level`、`_offset`、`_anchor_feat`、`_scaling`、`_rotation`、`_opacity` 参数以及 `mlp_opacity`、`mlp_cov`、`mlp_color` 三个 MLP 权重；PBR 模型额外需要 `mlp_albedo`、`mlp_roughness`、`mlp_matallic` 和 `Hybridlight` 权重。

### GPU 架构适配

预编译的 `librasterizer.so` 支持 SM 70/75/86。若 GPU 架构不同，使用 CMake 重新编译：

```bash
cd submodules/light_gaussian
mkdir -p build && cd build
cmake .. && make
```
